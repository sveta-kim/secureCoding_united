📄 XML Injection 테스트

XML Injection이란?
애플리케이션에서 외부 입력값을 검증하지 않고 XML 쿼리(XPath)에 삽입할 때, 공격자가 임의의 XPath 구문을 삽입하여 인증을 우회하거나 민감한 데이터를 조회할 수 있는 취약점입니다.

📝 테스트용 XML 데이터 구조

<?xml version="1.0" encoding="UTF-8"?>
<collection>
  <users>
    <user name="alice">
      <home>/home/alice</home>
    </user>
    <user name="bob">
      <home>/home/bob</home>
    </user>
    <user name="admin">
      <home>/root</home>
    </user>
  </users>
</collection>

공격 예제

정상 입력: alice → alice의 홈 디렉토리 조회

악의적 입력:

# XPath Injection으로 모든 사용자 조회
' or '1'='1

# 실행되는 XPath 쿼리 (취약한 경우)
/collection/users/user[@name='' or '1'='1']/home/text()

# 결과: 모든 사용자의 홈 디렉토리가 조회됨
/home/alice
/home/bob
/root

💡 다양한 XPath Injection 페이로드

  • ' or '1'='1 - 모든 데이터 조회
  • ' or 1=1 or '1'='1 - 조건 우회
  • admin' or '1'='1 - 특정 사용자와 OR 조건
  • ' or count(//user)>0 or '1'='1 - 복잡한 구조 탐색

💡 취약한 코드 vs 안전한 코드

# ❌ 취약한 코드
user_name = request.POST.get('user_name')
query = f"/collection/users/user[@name='{user_name}']/home/text()"
results = root.xpath(query) # 위험! 입력값이 직접 쿼리에 삽입됨

# ✅ 안전한 코드 (Parameterized XPath)
user_name = request.POST.get('user_name')
query = "/collection/users/user[@name = $paramname]/home/text()"
results = root.xpath(query, paramname=user_name) # 안전! 파라미터 바인딩

🛡️ 방어 방법

  • Parameterized XPath 사용: XPath 변수를 사용하여 입력값 분리
  • 입력값 검증: 특수문자(', ", [, ], /) 필터링
  • 화이트리스트: 허용된 문자만 입력 받기
  • 최소 권한: XML 데이터에 최소한의 권한만 부여
  • XXE 방어: External Entity 비활성화

⚠️ 실제 공격 시나리오

  • 1. 공격자가 XML 기반 인증 시스템의 취약점 발견
  • 2. XPath Injection으로 인증 우회 (admin' or '1'='1)
  • 3. 모든 사용자의 정보 조회 가능
  • 4. 관리자 계정으로 시스템 침투
  • 5. 민감한 설정 파일(/root) 접근
