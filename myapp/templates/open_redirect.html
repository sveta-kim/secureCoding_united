🔗 Open Redirect 테스트

Open Redirect란?
웹 애플리케이션에서 사용자 입력값을 검증하지 않고 리다이렉트(URL 이동)에 사용할 때, 공격자가 악의적인 사이트로 사용자를 유도할 수 있는 취약점입니다. 피싱 공격, 악성코드 유포 등에 악용될 수 있습니다.

💡 학습 안내

실제 환경에서는 취약한 코드 실행 시 즉시 리다이렉트되지만,
학습 목적으로 결과 페이지에서 무엇이 문제인지 확인할 수 있도록 구성했습니다.

🚀 빠른 테스트

✅ 내부 경로 (안전): ?url=/myapp/&mode=safe
💡 상대 경로는 내부 페이지로 안전하게 이동
✅ 화이트리스트 도메인 (안전): ?url=https://example.com&mode=safe
💡 허용 목록에 있는 도메인으로 이동 가능
❌ 외부 사이트로 리다이렉트 (취약): ?url=https://google.com&mode=vulnerable
⚠️ 검증 없이 구글로 리다이렉트 허용됨 (취약점!)
✅ 외부 사이트 차단 (안전): ?url=https://google.com&mode=safe
🛡️ 화이트리스트에 없어 차단됨

공격 예제

정상 입력: /myapp/ → 내부 페이지로 이동

악의적 입력:

# 외부 피싱 사이트로 리다이렉트
?url=https://evil-phishing-site.com/fake-login

# 프로토콜 우회 시도
?url=//evil-site.com

# JavaScript 프로토콜 악용
?url=javascript:alert('XSS')

💡 실제 공격 시나리오

  • 1. 공격자가 정상적인 웹사이트의 Open Redirect 취약점을 발견
  • 2. 악의적인 URL을 포함한 링크를 제작하여 이메일/SNS로 배포
  • 3. 사용자는 신뢰하는 도메인이 포함된 링크를 클릭
  • 4. 정상 사이트를 거쳐 피싱 사이트로 자동 리다이렉트
  • 5. 사용자는 정상 사이트에서 이동한 것으로 착각하여 개인정보 입력

💡 취약한 코드 vs 안전한 코드

# ❌ 취약한 코드
def redirect_view(request):
  url = request.GET.get('url')
  return redirect(url) # 위험! 검증 없이 바로 리다이렉트

# ✅ 안전한 코드 (화이트리스트 방식)
ALLOWED_DOMAINS = ['example.com', 'trusted-site.com']

def safe_redirect_view(request):
  url = request.GET.get('url')
  
  # 상대 경로만 허용
  if url.startswith('/') and not url.startswith('//'):
    return redirect(url)
  
  # 절대 경로는 화이트리스트 검증
  from urllib.parse import urlparse
  parsed = urlparse(url)
  if parsed.netloc in ALLOWED_DOMAINS:
    return redirect(url)
  
  return HttpResponse("허용되지 않은 도메인입니다.")

방어 방법

  • 화이트리스트: 허용된 도메인 목록만 리다이렉트 허용
  • 상대 경로 우선: 내부 경로(/myapp/)만 허용
  • URL 파싱: urlparse로 도메인 추출 후 검증
  • 프로토콜 검증: http/https만 허용, javascript: 등 차단
